# Unity 工程与启动流程

[总索引](../README.md)

状态：未完成

## 功能简介

维护 Windows 离线工程、启动、验证和构建发布的共用约定；各玩法的专属方案归所属页面。

## 工程约定

工程与依赖版本由工程配置和现有启动工具确定，文档不重复登记。启动、存档选择和创角分别见[启动页](../startup/startup.md)、[设置与存档](../settings/settings-and-save.md)和[角色创建](../character/character-creation.md)。

反编译的稀疏着色器通过公共构建模块保留官方实际存在的关键字组合；新增或复用此类资源时同步绑定其程序范围，构建前核对覆盖范围，不能编译不存在的组合或用其他程序替代。

## 验证约定

- 按影响范围完成规则测试、工程静态检查、Unity 导入／编译和工程验证。仅修改说明文档时检查内容和链接；涉及游戏行为或表现时须运行对应流程。
- Unity 编辑器及带窗口的验证均通过仓库现有内置屏启动工具运行，按硬件身份定位，不能使用系统主屏或固定屏号代替。保留定位守护，不停用或绕过。
- 已有启动前检查的验证流程在 Windows 可用物理内存低于 4 GiB 或可用虚拟内存低于 8 GiB 时可暂缓启动。Unity 进程启动后可以按需使用 Windows 可分配的全部内存。
- 启动前核对整个执行路径能否保持后台且不激活窗口；测试静音、输入仅注入测试进程，截图直接存文件，不操作系统真实输入、剪贴板或显示模式。不能保证时暂停该项。
- 检查实际模拟点击、键盘或拖拽、遮挡和渲染，并验证状态及磁盘恢复；直接调用业务回调只证明逻辑，视觉检查必须有图形渲染。测试静音仍检查音频事件和播放状态，不修改用户音量存档。
- 隔离工程复用公共依赖装配工具，按真实引用闭包准备代码、元数据和隐式资源，避免复制一套依赖规则；装配成功不等于玩法通过验证。
- 完整源码验证工程可从当前工作区复制工程输入并核对一致性，使用独立导入缓存；准备期间源码须保持稳定，失败后重新准备。此验证输入与发布所需的已提交版本快照分别管理。
- 验证开始前设置本会话验证目录和仓库根目录；临时产物管理见[素材管理](../asset-management.md#验证临时产物)。失败修复后重跑，如实区分已执行、未执行与阻塞。

## Windows 构建与发布

- 发布游戏版本时，按[全局约定](../../AGENTS.md)真实运行构建产物，验证入口、受影响流程、模拟输入、画面和存档。
- 使用现有发布入口，从明确的已提交版本准备独立构建输入；不把其他会话的未提交修改混入交付。复用持久发布缓存及增量资源，只有变更确需时才清理缓存。
- 会话要求禁用 worktree 时，发布入口使用源码快照模式，从指定提交导出完整源码、资源和工程配置；独立工程保留自己的导入缓存，继续执行相同的来源完整性检查。
- 正式入口、ASCII 命名和快捷方式遵守[全局约定](../../AGENTS.md)。运行中的游戏不覆盖发布；只替换受管理的运行文件，不镜像删除用户目录，不触碰存档、选择记录或未知文件。
- 提交与发布必须一致，交付时说明可验证范围及未完成内容；空框架或仅工具链构建不算游戏功能完成。
