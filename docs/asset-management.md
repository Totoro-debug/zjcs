# 素材管理约定

[返回文档索引](README.md)

本页维护素材、来源及临时产物的共用约定；模块专属方案归所属功能或地图页。

## 目录与版本管理

- 工程代码与独立素材载荷分开保存，官方迁移代码与单机适配分开管理；素材目录不放手写代码。运行所需资源必须随 Windows Player 交付。
- 原始输入和工具缓存放在 `.tools/`；可复用缓存优先使用，只重新导入受影响素材。保留稳定元数据和引用身份，清理前核对动态加载、生成器及存档影响。
- Git 忽略规则只排除明确的缓存和产物，不屏蔽应交付的代码、素材、配置或来源清单。大文件沿用现有 LFS 机制。
- 换行符沿用 Git 默认设置，不为普通文件另设换行规则；保留 LFS 与其他资源处理约定，不做全库重新规范化。
- 必要来源凭据以机器可核验的清单为准，参见[官方来源约定](../assets/reference/SOURCES.md)。文档不重复输入输出哈希、对象编号、资源数量或转换程序清单。
- 完整快照仅在迁移、素材交付或备份需要时生成；锁定记录须与实际快照一致，未入快照的素材不能声称已备份。

## 验证临时产物

验证工程、缓存、Player、编译输出、日志、截图和隔离存档统一放在 `output/validation/<模块>-<GUID>/`，使用现有验证工作区工具创建和清理。

每次会话明确设置验证目录及仓库根目录，使用绝对路径并等待子进程退出。只清理本会话创建且已停止使用的产物；截图须先实际查看，持续复用的发布缓存不按一次性产物清理。

窗口、输入与静音要求见[工程运行约定](features/unity-project.md#验证约定)。

## 官方提取与转换

先核实 APK 中的实际资源、对象和依赖，再核对已下载官方云端资源；目录索引不代表文件已取得，加载失败不代表资源缺失。不同输入独立保留身份，不混用缓存或调整预期哈希绕过校验。

缺少反编译结果时继续恢复相关程序集和依赖。来源版本只用于溯源，不作为资源加载或功能开关。

## Android 资源迁移到 Windows

先确认模块完整依赖，再恢复 Unity 原生资产、脚本、shader 和插件，建立显式本地绑定；复制 Android bundle 不等于 Windows 可用。

编辑器与资源兼容性必须实际验证。依赖缺失、解码失败、脚本重绑定、shader 编译或渲染异常应逐项定位，不能以替代美术或修改来源凭据规避。

## Spine 角色动画迁移决策

角色动画沿用[角色创建中的免费原生迁移方案](features/character/character-creation.md#spine-迁移决策)，共享调用方引用同一决定。
