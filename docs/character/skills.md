## 实现要点

按官方描述迁移主动战技、被动秘法、被动与触发效果、子技能、增益与减益、动画及人物动作；已确认的单机边界只在对应技能的实现要点中简述。

合成、装配、升级、进阶与存档使用公共培养及界面流程，技能差异由官方配置驱动。

装配仅使用已持有且职业可用的技能；空战技方案允许进入战斗，正常结算回合与被动，不自动补战技。

连锁攻击遵循已确认的[单机目标选择规则](../combat/battle-execution.md#自定义实现)。

共享战斗模块负责读取数值配置、展开命中图、计算伤害、处理状态与触发，以及播放原生技能图。新迁移技能的当前配置与旧共享输入不同时，使用带独立来源和完整性校验的技能数据包，核对替换前实体后加载，保留各自来源。技能包可将培养组、等级和品阶数值限定于自身实体，复用官方数值计算，避免改变仍使用旧来源的同组技能；缺少引用的数值表时拒绝加载。四阶配置校验覆盖职业绑定、实体引用和主动战技的演出绑定。战斗冒烟测试覆盖主动及内置战技的选取和施放。

官方输入与素材按原始字节校验；生成的文本凭据引用可按其声明的 LF 规范化规则校验，更新引用前须重新核验其记录的来源与输入。

施法监听按官方配置组合元素与动作条件，使用共用状态、属性和回合生命周期处理叠层、刷新与到期；触发计数和状态来源随战斗存档恢复。子技能是否继续触发秘法，由原配置的触发开关和状态白名单决定。

状态开场附加的子状态与禁用操作复用官方目标枚举；创建者、应用者和触发来源分别解析，开场不存在的触发来源或目标保持为空。

连续追加施放使用共用子技能创建、培养继承和动作结束调度，保持原目标与各段原生时长；依技能说明在概率失败或目标被击败时中断。追加段不再次消耗普通槽位次数或冷却，旧存档遗漏的追加技能定义从校验后的官方组件恢复。

直接同步生命的子技能沿用原始命中图生成施放快照、命中记录和伤害回执，不重复计算伤害或选取目标；致死、溢出与非命中扣血也保留原生演出所需的目标和时序。

五阶及以上职业仅保留既有技能说明，不计入本次完成范围。

三、四阶技能须逐项验证描述、数值、全部适用效果及分支、原生演出、存档恢复和 Windows Player 中的受影响流程，全部通过后标为已完成。

Windows 技能流程可在同一验证进程中顺序执行；每个技能使用独立测试存档并保留各自的战斗结果，全部通过后才记录整组成功。
